# led-gcc-stm32

![Language](https://img.shields.io/badge/language-C-blue)  [![English](https://img.shields.io/badge/lang-English-blue)](README.md) [![中文](https://img.shields.io/badge/lang-中文-red)](README.zh-CN.md)


A complete STM32F103C8T6 (Blue Pill / YT32M1) LED blink project for VS Code, with build, flash, and debug fully configured out of the box.

Build is powered by GNU Make and the ARM GCC toolchain. Flashing uses OpenOCD over CMSIS-DAP (SWD). Debugging uses the Cortex-Debug VS Code extension with SVD peripheral view.

## Features

- **One-command build** — `make all` produces `.elf`, `.hex`, and `.bin` outputs
- **One-command flash** — `make flash` programs the MCU via OpenOCD
- **One-key debug** — Press `F5` in VS Code to start a full Cortex-Debug session
- **STM32CubeMX compatible** — The `.ioc` project file is included; regenerate code with CubeMX when needed
- **SVD peripheral view** — `STM32F103xx.svd` is configured for register-level debugging
- **HAL library** — Uses STM32F1xx HAL driver (generated by CubeMX)

Make sure `arm-none-eabi-gcc`, `make`, and `openocd` are on your `PATH`.

## Quick Start

### 1. Clone

```bash
git clone https://github.com/jrtxio/led-gcc-stm32.git
cd led-gcc-stm32
```

### 2. Build

```bash
make all
```

Output files are generated under `build/`:

| File | Description |
|------|-------------|
| `build/LED.elf` | ELF executable (used for debugging) |
| `build/LED.hex` | Intel HEX format (used by some flash tools) |
| `build/LED.bin` | Raw binary |
| `build/LED.map` | Linker map file |

### 3. Flash

Connect your CMSIS-DAP probe to the target board via SWD, then:

```bash
make flash
```

This calls OpenOCD with the custom config `stm32yt32m1.cfg`, programs `build/LED.elf`, verifies, and resets the MCU.

### 4. Debug in VS Code

Press `F5` to launch a Cortex-Debug session. The debugger will:
- Start OpenOCD using `stm32yt32m1.cfg`
- Load `build/LED.elf`
- Run to the `main()` entry point
- Enable the SVD peripheral register view for `STM32F103xx`

### 5. Clean

```bash
make clean
```

## Make Targets

| Target | Description |
|--------|-------------|
| `all` (default) | Build `.elf`, `.hex`, and `.bin` |
| `flash` | Flash the `.elf` to the target via OpenOCD |
| `clean` | Remove the `build/` directory |

## Hardware Configuration

- **MCU**: STM32F103C8T6 (Cortex-M3, 72 MHz, 64 KB Flash, 20 KB SRAM)
- **Board**: YT32M1 (Blue Pill compatible)
- **Clock**: HSE 8 MHz, PLL x9 = 72 MHz system clock
- **Debug probe**: CMSIS-DAP via SWD (20 MHz adapter speed)
- **LED GPIO**: PB0 (configured in `LED.ioc` / `Core/Src/gpio.c`)

## OpenOCD Configuration

The file `stm32yt32m1.cfg` configures OpenOCD for the YT32M1 board:

```
source [find interface/cmsis-dap.cfg]
transport select swd
source [find target/stm32f1x.cfg]
adapter speed 20000
```

If you use a different debug probe (ST-Link, J-Link, etc.), modify this file accordingly.

├── LED.ioc                          # STM32CubeMX project file
├── startup_stm32f103xb.s            # Startup assembly (vector table, init)
├── STM32F103C8Tx_FLASH.ld           # Linker script

│   └── Src/
│       ├── main.c                   # Main application (HAL init, clock, GPIO)
│       ├── gpio.c                   # GPIO initialization (LED pin)

│       ├── stm32f1xx_it.c           # Interrupt handlers

## Customization

### Changing the target MCU

1. Modify `LED.ioc` in STM32CubeMX and regenerate code
2. Update the Makefile: change `C_SOURCES`, `C_DEFS`, `C_INCLUDES`, `LDSCRIPT`, `CPU`, and `ASM_SOURCES`
3. Replace `startup_stm32f103xb.s` and `STM32F103C8Tx_FLASH.ld` with the new files
4. Update `stm32yt32m1.cfg` and `STM32F103xx.svd` for the new target

### Adding source files

Add new `.c` files to the `C_SOURCES` list in the `Makefile`.
